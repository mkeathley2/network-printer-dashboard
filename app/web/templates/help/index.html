1. Getting Started

The Printer Dashboard watches your networked printers in real time, tracks toner and drum supply levels, records page counts, and alerts you (via email) when something needs attention. Everything you need is available from the navigation bar at the top of every page.

Top navigation

  • Dashboard — live overview of every active printer
  • Discover — scan a subnet to find printers to add
  • Alerts — chronological log of every alert ever raised
  • Reports — six analytical reports with CSV export
    • {% if current_user.is_admin %}
  • Config Admin — all settings live here
    • {% endif %}

Your account menu

Click your username in the top-right corner to open the account menu. From there you can Change Password, open this Help page, or Log out.

Tip: If an admin creates your account with an email address, you'll receive a welcome email with a temporary password. The first time you log in, you'll be required to set a new password before you can access any other page.

2. Dashboard Overview

The Dashboard shows every active printer as a tile. Each tile summarizes the printer's current status and its lowest supply level.

Status dots

  • Green — printer is online and responding to SNMP
  • Red — printer is offline (missed several polls)
  • Gray — not yet polled or status unknown

Supply bars

  • Green — above the warning threshold (healthy)
  • Orange — below warning threshold
  • Red — below critical threshold

Filter bar

Above the tiles, use the filter pills to narrow down by location, status, or search by name. Filters stack — picking a location and "online only" shows only online printers at that location.

3. Managing Printers

Adding a printer {% if not current_user.is_admin %}Admin{% endif %}

Admin users click a printer tile → the printer detail page opens. To add a new one, use Discover to scan a subnet (below) OR click "Add Printer" from the printer list page. You provide the IP address, optionally a display name, and the SNMP community string (usually public). The first poll runs automatically.

Network Discovery — scan & bulk-add {% if not current_user.is_admin %}Admin{% endif %}

The Discover tab (top nav) scans a whole subnet for SNMP-responsive printers so you don't have to add them one IP at a time.

  1. Enter a CIDR range (e.g. 10.47.69.0/24) and the SNMP community string (default public), then click Start Scan. Progress updates live.
  2. When the scan finishes, each responding host appears as a row marked New or Known (already on the dashboard), with detected vendor and model.
  3. To add printers, you have three options:
    • Tick the checkboxes for the specific printers you want (or use the header "select all" checkbox), choose a Location from the dropdown, and click Add Selected. The counter shows how many are selected.
    • Add All New — adds every new printer at once, also into the chosen Location.
    • Add One — the per-row button adds a single printer (configure its Location on the printer page afterward).

Newly-added printers are polled automatically in the background, and any matching spreadsheet import data (assigned person, SQL number, etc.) is applied. Recent scans are listed on the left and can be re-run or removed.

The printer detail page

Everything you need is on one page:

  • Asset info — display name, IP, vendor, model, serial, assigned person, SQL number, phone ext., web login credentials
  • Supply Levels — live bars for every toner, drum, or ink cartridge
  • Toner Replacement History — every time a cartridge was swapped, with an admin-editable cost field
  • History link — opens the per-printer History page (next section)
  • Recent alerts — the last dozen alerts raised for this printer

The History page

Click the History button on a printer's detail page to open a deeper view with depletion estimates and historical charts.

  • Date range pills at the top right — switch between 7 days / 30 days / 90 days / All time (default: 90 days)
  • Active Supplies table — for every cartridge: color, status (OK / Warning / Critical), current %, consumption rate (% per day), days remaining at the current rate, predicted empty date
  • Pages-per-day card — average page output over the selected window
  • Supply Levels Over Time chart — one line per supply, with vertical dashed markers showing each replacement event (color-coded to the cartridge)
  • Page Count Over Time chart

Depletion estimates are replacement-aware: the regression line is fitted only to readings after the most recent toner_replaced / drum_replaced event, so days-remaining stays accurate right after you swap a cartridge.

Actions available on the detail page

  • Poll Now — force an immediate SNMP poll instead of waiting for the scheduler
  • History — open the per-printer History page (charts + depletion estimates)
  • Open Web UI — open the printer's own built-in web interface in a new tab (uses the stored web username/password if you've saved them)
  • Create Helpdesk Ticket — email a ticket to the configured helpdesk address
  • Resend Alerts — clear dedup flags so active warnings are re-emailed on the next poll (admin only)
  • Edit — change the display name, location, SNMP community, and asset fields (assigned person, SQL number, computer, phone ext., web credentials) (admin only)
  • Set Thresholds — override the site-wide warning/critical percentages for this one printer (admin only)
  • Remove Printer — soft-delete. Printer data is kept; printer can be restored from Config → Removed Printers (admin only)

Moving printers between locations {% if not current_user.is_admin %}Admin{% endif %}

Three ways, depending on how many you're moving:

  • One printer — change the Location dropdown on its Edit page.
  • A hand-picked set — on the Printers list page, tick the checkboxes (or select-all), choose a location in the bar above the table, and click Move Selected.
  • Everything at a location — on Config → Locations, use the "move printers" action on the source location's row, pick the target, and all of its printers move at once.

Finding duplicate printers

The same physical printer can end up on the dashboard twice — typically when it was added locally and found by a remote agent, or re-discovered at a new IP after a DHCP change. The Config → Duplicates tab (admin only) groups active printers that share the same serial number (the reliable key — names and IPs can legitimately differ or collide across sites). A red badge on the tab shows how many duplicate groups currently exist.

Each group shows the rows side-by-side (name, IP, model, location, whether it came from a remote agent or was added locally, and last-seen time). The row with the most recent successful poll is badged Most recent — that's usually the one to keep. Click Remove on the other; it's a soft-delete, so history is kept and it can be restored from the Removed Printers tab if you picked wrong.

4. Supply Levels & Alerts

How supply levels are read

Every poll, the dashboard queries each printer's SNMP supply table. Level is reported as a percentage of capacity. Some older printers only report a raw count vs. max — the dashboard converts that to a percentage automatically.

Brother mono lasers (HL-L2xxx, DCP/MFC-L2xxx, …) don't publish the toner level in the standard supply table at all — they answer "unknown, at least one unit remaining". The dashboard (and remote agents) read the real percentage from Brother's proprietary maintenance data instead, so these models show accurate toner levels too.

Vendor & hostname: the dashboard recognizes HP, Brother, Canon, Kyocera, Ricoh, and Konica Minolta (bizhub); anything else is monitored as a generic SNMP printer. The hostname comes from the printer's SNMP system name, or — when that's blank (common on Konica Minolta) — falls back to its network (reverse-DNS) name, matching what you see in the printer's own web interface.

Warning vs. Critical thresholds

Default thresholds are 15% (warning) and 5% (critical). When a supply crosses below warning for the first time, a warning email is sent. When it later crosses critical, a critical email is sent. Each email is sent once per supply lifecycle — a new cartridge install resets the flags so the cycle starts over.

Toner replacement detection

When the supply level jumps upward significantly (e.g. 3% → 98%), the system records a toner_replaced event. You can enter the cost of the replacement from the printer detail page so it flows into the Toner Cost report.

Offline alerts

If a printer fails to respond to the scheduled poll several times in a row (default: 3 consecutive misses), it's marked offline and an offline alert email is sent. When it responds again, a back-online email is sent.

Emails only send if SMTP is configured. If you're not getting alert emails, start with Config → Email / SMTP and send a test email from that page.

Dashboard links in emails

Every alert email and helpdesk ticket includes a View Printer in Dashboard link (or "View Printer" + "View History" for tickets) when the public URL is set under Config → Remote Agents. The link uses the same Tailscale Funnel / public URL you've configured, so recipients can jump straight to the printer with one click.

Auto-helpdesk-ticket on critical {% if current_user.is_admin %}Admin{% endif %}

When enabled (Config → Alert Settings), the dashboard automatically files a helpdesk ticket the moment any toner or drum hits the critical threshold — alongside the normal critical email. It only fires once per supply lifecycle, so a printer that's been at 4% for weeks won't generate duplicate tickets. The cycle resets on cartridge replacement.

Cost-entry helpdesk ticket on replacement {% if current_user.is_admin %}Admin{% endif %}

When enabled (Config → Alert Settings), every detected toner or drum replacement also files a helpdesk ticket asking the on-site tech to record the replacement cost in the dashboard — with a direct link straight to the Replacement History card and step-by-step instructions. This keeps the Toner Cost and Cost Per Page reports accurate without anyone needing to remember the manual step. Printers flagged Supplies under contract (on the Edit page) never get this ticket — vendor-supplied toner has no cost to record.

Don't want to wait for a real replacement to see the email? On the same card you'll find a Send Test Email button that fires a sample ticket immediately using your most recent real replacement event (or placeholder data if none exist).

5. Reports

The Reports tab (top nav) has six pre-built reports. All are visible to every signed-in user. Each report has a filter bar (date range, printer, etc.), a chart, a sortable table, and a Download CSV button for exporting the underlying data.

Print Volume

Pages printed per printer in a date range. Group by printer, person, or location.

Page Count Over Time

Multi-line chart of cumulative page count per printer over time.

Toner Cost

Every toner replacement with the cost you entered, plus a Cartridge column showing which model was swapped (e.g. "Black Cartridge HP 87X") so you can track prices per SKU. Totals by printer and color.

Cost Per Page

Total toner cost ÷ total pages printed. The printer efficiency metric.

Consumption Rate

How fast each supply depletes (% per day), with projected days remaining.

Reliability

Offline event counts per printer. Higher numbers = more unreliable printer.

Entering replacement costs

Admin: open a printer detail page, scroll to Toner Replacement History, and fill in the Cost field for a replacement row. The cost immediately flows into the Toner Cost and Cost Per Page reports.

Printers with supplies under contract {% if current_user.is_admin %}Admin{% endif %}

Some printers get their toner from a vendor under a service contract — there's no per-cartridge price to log, and including them would skew your cost numbers. On the printer's Edit page, tick Supplies under contract (under "Cost Tracking"). For flagged printers:

  • Replacements are excluded from the Toner Cost and Cost Per Page reports (rows, totals, charts, CSVs, and scheduled emails)
  • No cost-entry helpdesk ticket fires when a cartridge is replaced
  • The printer's own Replacement History card still shows every swap (marked Contract), and low-toner alerts, predictive tickets, and critical tickets all work normally — someone still has to change the cartridge

Any costs logged before flagging are retained, just hidden — untick the box and they reappear in the reports.

Scheduling email reports {% if current_user.is_admin %}Admin{% endif %}

Any of these reports (except "Page Count Over Time", which is chart-only) can be emailed automatically on a schedule. Admins: go to Config → Alert Settings → Scheduled Report Emails, set a recipient address, and pick a frequency per report:

  • Daily — 7 AM site-local time, looking back 24 hours
  • Weekly — Monday at 7 AM, looking back 7 days
  • Monthly — 1st of the month at 7 AM, looking back 30 days

Each email contains the top 50 rows as a styled HTML table plus the full data as a CSV attachment, with a "View Full Report" button linking back to the dashboard. Each row has a "Send Now" button to test the email immediately (uses the weekly window).

6. Remote Agents Admin

A Remote Agent is a small background service running on a machine at another site. It scans the local subnet for printers and reports back to this central dashboard over HTTPS — no VPN or port-forwarding required. Use agents when you need to monitor printers on networks the dashboard server can't reach directly.

Distribution: Windows .exe, Linux/Pi .py

On Windows the agent is a standalone printer_agent.exe (about 30 MB) — no Python install required on the target machine. GitHub Actions builds it automatically on every release; the installer pulls it directly from GitHub Releases. On Raspberry Pi / Linux the agent is a small Python script.

Because the .exe is launched by Task Scheduler running as SYSTEM (not by Explorer), there is no Windows SmartScreen prompt — even when deploying via ConnectWise Backstage or another RMM.

Adding an agent

  1. Go to Config → Remote Agents.
  2. Enter a name (a Location with the same name is auto-created).
  3. Leave the subnet blank (recommended) — the agent detects the machine's own subnet on first run (outbound interface + the actual mask from ipconfig / ip addr) and reports it back to the dashboard. Enter a CIDR only when the machine spans multiple subnets or should scan a different one.
  4. Click Create Agent.
  5. Copy the Windows PowerShell or Raspberry Pi bash one-liner displayed.
  6. Paste it into an elevated PowerShell (Windows) or shell (Pi) on the remote machine.

Managing agents

The agents table shows a Printers column — the number of active printers each agent has found. An agent stuck at 0 either hasn't completed a scan yet or is scanning the wrong subnet; once you've confirmed it's not needed, delete it. Each agent row also has action buttons:

  • Rescan Now — tell the agent to scan immediately
  • Force Update — push the latest agent version
  • Edit Interval — change scan frequency
  • Edit Subnet — push a new subnet (blank = auto-detect)
  • Assign Location
  • Regenerate API Key
  • Delete — if the agent has checked in: queues an uninstall on next check-in; if the agent has never checked in OR is offline (stale): immediately hard-deletes the row.

Auto-update

When the dashboard and an agent fall out of version sync, the dashboard auto-queues an update command on the next check-in. An Outdated badge appears in the Version column, and the Update All Outdated button in the agents card header lets you push updates to multiple agents at once.

On Windows the agent can't directly overwrite its own running .exe, so it downloads printer_agent.exe.new, writes a tiny _update_helper.cmd that stops the scheduled task, swaps the file, and restarts the task, and then exits to let the helper finish. Total downtime: about 5 seconds. On Linux/Pi the agent simply rewrites itself and restarts the systemd service.

Manually triggering a check-in

On the remote machine:

# Windows
Start-ScheduledTask -TaskName "PrinterAgent"

# Linux / Raspberry Pi
sudo systemctl restart printer-agent

7. User Accounts & Security

Roles

There are three roles, in increasing order of privilege:

  • Viewer — read-only. Can see all printers, reports, and alerts. Cannot edit anything.
  • Admin — can add/edit/remove printers, run discovery, manage users, change all settings, manage remote agents, and download backups. Cannot run the destructive Factory Reset or Restore-from-backup. This is the right role for most techs.
  • Super Admin — everything an Admin can do plus Factory Reset and Restore-from-backup. Only a Super Admin can grant the Super Admin role or change another Super Admin's account, so a regular admin can't self-elevate.

On upgrade to the version that introduced Super Admin, all existing Admin accounts were promoted to Super Admin so nobody lost access. If you want your techs to be plain Admins (no Factory Reset / Restore), demote them under Config → Users.

Temporary passwords & forced change

When an admin creates a new user (or resets an existing user's password via Send Reset Email), the system generates a random temporary password. On first login with that password, the user is redirected to a Set Your Password page and cannot access any other page until they choose a new password (minimum 8 characters).

Changing your own password

Click your username in the top-right → Change Password. You'll need to enter your current password to confirm.

{% if current_user.is_admin %}

Resetting another user's password Admin

Go to Config → Users. For each user you have two options:

  • Send Reset Email — generates a new temp password, emails it to the user, forces change on next login. Requires an email address on file.
  • Manual set — type a password and click Set. Use this if the user has no email address or you need immediate offline access.

8. Admin Configuration Admin

Everything below lives under Config (the gear icon in the top nav).

Email / SMTP

Configure the outgoing mail server. Three auth modes are supported: STARTTLS (port 587 — most common), SSL/TLS (port 465), and None (local relay). Send a test email from this tab to verify.

Alert-To is where all alert emails go. Helpdesk email is where manually-created tickets (from a printer's detail page) are sent.

Thresholds

Set the site-wide warning and critical percentages for supply level alerts. Any printer can override these from its detail page (the override goes onto that printer's row in the database).

Reset Per-Printer Overrides — the same tab has a one-click button that bulk-clears every per-printer override at once. Useful when you change the site default and want all printers to inherit the new value (the site default doesn't automatically apply to printers with their own overrides). The button shows the count of printers currently overridden and is disabled when there's nothing to clear.

Predictive Toner Alerts

When enabled, a scheduled job runs hourly and uses linear regression on recent supply-level readings to predict when each cartridge will run out. If predicted to be empty within N days (default 7), a helpdesk ticket is auto-generated — once per supply lifecycle. Set the days threshold and minimum data-point count from the Alert Settings tab.

Auto-Ticket on Critical

On the Alert Settings tab, the Auto-Ticket on Critical card has a single on/off toggle. When ON, every toner or drum that crosses below the critical threshold generates a helpdesk ticket alongside the alert email. Deduped per supply lifecycle (resets on cartridge replacement). Requires a helpdesk email on the SMTP tab.

Cost-Entry Ticket on Replacement

On the Alert Settings tab, the Cost-Entry Ticket on Replacement card has an on/off toggle and a Send Test Email button. When the toggle is ON, every detected toner/drum replacement fires a separate helpdesk ticket that asks the tech to record the replacement cost — with a one-click link to the Replacement History section of that printer's detail page. The Test button sends a sample so you can preview the format without waiting for a real event.

Scheduled Report Emails

The Scheduled Report Emails card on the Alert Settings tab lets you schedule any of the five tabular reports. Set a recipient email, pick a frequency per report (Off, Daily, Weekly, Monthly), and the dashboard handles the rest. Each row also has a Send Now button so you can test what the email will look like without waiting for the schedule.

Locations

Tag each printer with a location. Locations power the filter bar on the dashboard and the grouping options in reports. Each row on the Locations tab has three actions:

  • Rename — fix typos; printers and agents keep pointing at the location (they're linked by ID, not name). Renaming to a name that already exists is blocked — to combine two locations, move the printers across, then delete the empty one.
  • Move printers — bulk-move every printer at this location to another location (or to "No location") in one click.
  • Delete — removes the location; its printers become unassigned.

Import

Upload an .xlsx spreadsheet to pre-populate printer asset fields (assigned person, SQL number, location, etc.). Rows match printers by IP. Pending records are applied to existing printers or auto-filled when a new printer with a matching IP is added.

Software Updates

The Updates tab compares the running version against the latest GitHub release. When a newer version is available, release notes are shown along with a copyable block of commands to run.

Why updates are applied manually: the dashboard intentionally does not have permission to modify its own host or containers. This keeps the attack surface very small — even in the unlikely event the web app is ever compromised, the attacker cannot use the app to pivot to the VM. To update, SSH into the server, pull the latest code, and rebuild the container. The whole process takes about a minute.

On the VM:

cd /path/to/network-printer-dashboard
git pull
docker compose up --build -d

Or save yourself the typing next time by creating an update.sh script in the repo with those three lines and making it executable (chmod +x update.sh).

Activity Log

Every administrative action (logins, setting changes, printer adds/edits, role changes, etc.) is recorded with timestamp, username, action type, target, and detail. Retained for 1 year, then old entries are auto-pruned. Exportable as CSV.

This is the admin audit trail only. It does not hold your toner replacement history, costs, or monitoring data — those live in separate tables and are kept permanently (see the FAQ below).

Backup & Reset

The Backup & Reset tab has three areas:

  • Download Backup (any Admin) — exports the database as a zip of JSON files. Config-only skips telemetry/alert history for a small, fast snapshot; Full includes everything. Estimated sizes and row counts are shown.
  • Restore from Backup Super Admin — upload a previously-downloaded zip to overwrite the database. Because this replaces all data, it's restricted to Super Admins.
  • Factory Reset Super Admin — granular wipe by category (printers & history, locations, discovery history, staged imports, audit log, users, settings). Tick only what you want to clear; it requires an explicit "I understand" confirmation. Resetting users recreates the default admin/admin account as a Super Admin and logs you out.

9. Troubleshooting / FAQ

I'm not getting alert emails

  1. Check Config → Email / SMTP and send a test email.
  2. Verify the Alert-To address is set.
  3. Check the individual alert toggles under Config → Alert Settings.
  4. If using Gmail, make sure you're using an App Password, not your regular password.

A printer shows as "offline" but I know it's online

  1. Check that SNMP is enabled on the printer (some vendors ship it disabled).
  2. Verify the community string matches (usually public).
  3. Make sure the dashboard server can reach the printer IP (no firewall blocking UDP/161).
  4. Click Poll Now on the printer detail page to try again.
{% if current_user.is_admin %}

A remote agent shows "Outdated" but never updates

Log into the agent machine and trigger a check-in manually (see section 6 above). The agent will receive the queued update command on the next successful check-in.

I created an agent but never deployed it — how do I remove it?

Just click the Delete button on its row in the agents table. Agents that have never checked in are hard-deleted immediately (the old behavior of waiting for a remote uninstall ACK only applies to agents that have actually been deployed and are checking in).

An update failed — how do I roll back?

Since updates are applied manually via git pull, rolling back is just as easy: 

cd /path/to/network-printer-dashboard
git log --oneline -5              # find the previous good commit SHA
git reset --hard <previous-sha>
docker compose up --build -d

I get "SMTP not configured" but I already filled in settings

Check that all four fields (host, port, user, password) are filled and the auth mode is set correctly. If you set auth to "None", only the host field is required. If you changed settings in the UI, the new values take effect immediately — no restart required.

{% endif %}

How often are printers polled?

Default is every 60 minutes. {% if current_user.is_admin %}Change it at Config → Thresholds → Poll interval.{% endif %} Remote-agent printers are polled on the agent's own interval.

How long is data kept? Will I lose my toner replacement history?

No — your monitoring data is kept permanently. The following are never auto-pruned, so you can run reports across years of history:

  • Toner & drum replacement history (with the costs you entered)
  • Page-count and supply-level history (telemetry & supply snapshots)
  • Every alert event ever raised

The only thing that auto-prunes is the admin Activity Log (the who-did-what audit trail — logins, setting changes, etc.), which is kept for 1 year. That's completely separate from your printer/toner data.

The only way to remove monitoring data is a deliberate Factory Reset (Super Admin only) — nothing is deleted automatically.
