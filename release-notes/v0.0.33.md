## v0.0.33 — offline printers, remote clients, and replaced-printer handling

**Before updating: take a backup** (Config → Backup & Reset). This release adds columns and one table; the changes are additive and run automatically on start.

### Remote clients
- **Keep-awake** (Windows): the client asks Windows not to idle-sleep while it runs, so station PCs keep checking in. On by default; switch it off per client on Config → Remote Agents (cup / moon button). The screen can still turn off; lid, power button and shutdown are unaffected.
- **Log cap**: `agent.log` is trimmed to its newest 1 MB whenever it passes 2 MB. Oversized logs left by older versions are trimmed the first time the updated client starts.
- **Set the check-in interval for all clients at once** (Config → Thresholds). Per-client intervals still work.
- Interval and keep-awake are now sent in every check-in reply, so a setting can no longer be lost behind a queued update.

### Offline printers
- **Long-offline review ticket**: one helpdesk ticket when a printer has been offline 15 days (adjustable, 0 = off), asking whether it was replaced, moved or removed. Works even with the offline alert email turned off. Names a *possible* replacement when a newer printer has appeared at the same site.
- Only outages that reach the limit **after this update** create a ticket — no burst for printers that were already long gone.
- **Offline Ticket** button on any offline printer's page.
- **Offline Printers report** (Reports): everything offline right now and for how long, CSV export, a ticket button per row, and it can be scheduled like the other reports.

### Remote client stopped checking in
- One helpdesk ticket after 15 days of silence (adjustable), asking for it to be assigned to the person named in Config → Thresholds.
- While a client is not reporting, its printers do not generate their own offline tickets.

### Replaced printers (server-polled / VPN printers only)
- When a **different serial number** answers at a printer's IP on **two polls in a row**:
  - serial already known (on the dashboard or in Removed) → that printer *moved*: its record and history follow it, restored from Removed if needed;
  - serial never seen → a *new* printer: a fresh record is started at that IP;
  - the printer that used to be there goes to Removed with a note. Nothing is deleted.
- Remote-client printers are excluded (many sites share the same private IP ranges).

### Daily network scan (VPN sites)
- Once a day (5 AM dashboard time by default) the server scans every /24 it already polls a printer on, plus any extra subnets you list.
- New devices go to **Config → Discovered** for review — nothing is added automatically. **Approve** printers, **Ignore** everything else (remembered; can be un-ignored).

### Maintenance
- Releases now publish automatically (with `printer_agent.exe` attached) when `VERSION` changes on master.

### Deploy
1. Back up (Config → Backup & Reset).
2. On the VM: `cd /root/network-printer-dashboard && ./update.sh`
3. Remote clients update themselves at their next check-in.
